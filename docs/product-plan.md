# 刘看山推荐 —— AI 驱动的去中心化内容发现平台

> 让优质内容被看见，让每一个认真创作的人都不被埋没。

---

## 一、项目概述

### 1.1 项目名称
**刘看山推荐**（LiuKanShan Recommends）

### 1.2 参赛赛道
- 主赛道：🤝「引力场」—— 聚焦社区社交与内容分发
- 副赛道：🦊「刘看山」—— IP 智能新生计划

### 1.3 一句话描述
基于多 AI Agent 评审机制的去中心化内容推荐系统，让刘看山成为知乎社区的"内容伯乐"，通过内容质量本身（而非粉丝数）决定曝光，帮助优质新人内容破圈。

### 1.4 核心理念
> 在知乎，你的内容值多少分，不该由你有多少粉丝决定，而该由你写了什么决定。

## 二、痛点分析

### 2.1 现状问题

| 问题 | 描述 | 影响 |
|------|------|------|
| 马太效应严重 | 大V 内容天然获得更多曝光，新人内容难以被发现 | 新人创作积极性受挫，社区活力下降 |
| 推荐算法偏向流量 | 现有推荐机制倾向于已有高互动内容 | 深度、原创但小众的内容被埋没 |
| 内容自荐效果有限 | 现有自荐功能缺乏专业评审机制 | 自荐内容质量参差不齐，用户信任度低 |
| AI 生成内容泛滥 | 大量 AI 生成的"看似专业"内容充斥社区 | 真正的原创深度内容被稀释 |
| 缺乏内容质量反馈 | 创作者不知道自己的内容好在哪、差在哪 | 创作者无法针对性提升 |

### 2.2 目标用户

| 用户类型 | 画像 | 核心需求 |
|----------|------|----------|
| 新人创作者 | 粉丝 < 1000，有专业知识但缺乏曝光 | 让优质内容被更多人看到 |
| 深度创作者 | 擅长长文、技术文章，但不擅长"运营" | 内容质量被公正评价 |
| 内容消费者 | 希望看到真正有价值的内容 | 高效发现优质内容，过滤水文 |
| 社区管理者 | 知乎运营团队 | 发现优质新人，激活社区生态 |

### 3.2 核心功能模块

---

#### 📝 模块一：内容提交与申请推荐

**功能描述**：创作者在写完知乎内容（回答/文章/想法）后，可以将内容链接提交到「刘看山推荐」系统，申请 AI 评审。

**用户流程**：
1. 用户通过知乎 OAuth 登录系统
2. 粘贴自己的知乎内容链接
3. 系统自动抓取内容（通过知乎搜索 API）
4. 消耗 1 次推荐额度，进入评审队列
5. 等待 AI Agent 评审（预计 30 秒 - 2 分钟）

**规则限制**：
- 只能提交自己创作的内容（通过 OAuth 身份验证）
- 同一内容不可重复提交
- 内容发布时间需在 30 天以内

---

#### 🦊 模块二：多 Agent 评审引擎（核心）

**功能描述**：5 个具有不同"人格"和评审侧重的 AI Agent 对内容进行独立评审，最终由"刘看山"汇总给出综合评分和评语。

**Agent 评审团设计**：

| Agent | 角色名 | 人设 | 评审维度 | 权重 |
|-------|--------|------|----------|------|
| Agent 1 | 🎓 学术山 | 严谨的学者，注重逻辑和论证 | **内容深度**：论证是否充分、逻辑是否自洽、是否有独到见解 | 20% |
| Agent 2 | 📖 阅读山 | 挑剔的读者，注重阅读体验 | **可读性**：结构是否清晰、表达是否流畅、排版是否友好 | 15% |
| Agent 3 | 💡 创意山 | 追求新意，厌恶陈词滥调 | **原创性**：观点是否独特、是否有新角度、非搬运/洗稿 | 20% |
| Agent 4 | 🤝 社区山 | 资深知乎用户，了解社区文化 | **社区价值**：是否能引发有价值的讨论、是否对他人有帮助 | 15% |
| Agent 5 | 🔍 鉴真山 | AI 内容鉴别专家 | **人类原创度**：检测是否为 AI 生成/辅助生成内容 | 15% |
| 综合 | 🎯 专业度 | 由所有 Agent 综合判断 | **专业度**：引用是否准确、数据是否可靠、术语是否正确 | 15% |

**评分机制**：
- 每个 Agent 独立打分（1-10 分）
- 加权计算综合得分（满分 10 分）
- 综合得分 ≥ 7.0 分：🏆 推荐成功，进入「刘看山推荐榜」
- 综合得分 5.0 - 6.9 分：📝 给出改进建议，不推荐
- 综合得分 < 5.0 分：❌ 未通过评审

**AI 内容检测（鉴真山）详细设计**：

鉴真山 Agent 专门负责检测内容是否由 AI 生成，评估维度包括：

| 检测维度 | 说明 |
|----------|------|
| 语言模式分析 | 检测是否存在 AI 典型的表达模式（过度使用连接词、缺乏口语化表达等） |
| 个人经验判断 | 是否包含真实的个人经历、具体细节、情感表达 |
| 知识一致性 | 内容深度是否与作者历史创作水平一致 |
| 创意独特性 | 是否存在 AI 常见的"正确但无趣"的表达方式 |
| 结构模式 | 是否存在 AI 生成内容的典型结构模式（如过于工整的并列结构） |

**检测结果分级**：
- 🟢 高度原创（9-10分）：明显的人类创作特征
- 🟡 基本原创（7-8分）：可能使用 AI 辅助润色，但核心观点为原创
- 🟠 疑似 AI 辅助（4-6分）：较多 AI 生成痕迹，但有人工编辑
- 🔴 高度疑似 AI 生成（1-3分）：大量 AI 生成特征，缺乏人类创作痕迹

> 注意：AI 辅助创作不等于零分，我们鼓励合理使用 AI 工具，但核心观点和创意必须来自人类。

#### 🏆 模块四：刘看山推荐榜（推荐成功内容展示入口）

**功能描述**：所有通过评审（≥ 7.0 分）的内容，进入「刘看山推荐榜」，供社区用户浏览和发现优质内容。

**榜单设计**：

| 榜单类型 | 说明 | 更新频率 |
|----------|------|----------|
| 🔥 今日推荐 | 当天通过评审的高分内容 | 实时更新 |
| 📅 本周精选 | 本周综合评分 TOP 20 | 每周日更新 |
| 🌟 月度之星 | 本月最高分内容 TOP 10 | 每月 1 日更新 |
| 🏷️ 分类推荐 | 按领域分类（科技/人文/生活等） | 实时更新 |
| 🆕 新人专区 | 粉丝 < 1000 的创作者专属榜单 | 实时更新 |

**榜单页面功能**：
- 展示内容标题、作者、综合评分、各维度评分雷达图
- 一键跳转到知乎原文
- 支持按评分、时间、领域筛选和排序
- 显示刘看山的推荐语（从评审报告中提取）
- 用户可以对推荐内容点赞/收藏

**圈子联动**：
- 推荐成功的内容自动在知乎黑客松圈子发布推荐想法
- 想法内容包含：内容摘要 + 评分 + 刘看山推荐语 + 原文链接
- 社区用户可以在圈子内讨论和互动

#### 💰 模块五：额度管理系统

**功能描述**：通过额度机制控制推荐申请频率，激励优质创作。

**额度规则**：

| 规则 | 说明 |
|------|------|
| 初始额度 | 每周 3 次推荐申请额度 |
| 推荐成功奖励 | 每次推荐成功（≥ 7.0 分）+2 次额度 |
| 高分奖励 | 评分 ≥ 9.0 分额外 +3 次额度 |
| 额度上限 | 单周最多 15 次（防止刷量） |
| 低分惩罚 | 连续 3 次评分 < 5.0，下周额度减半 |
| 额度过期 | 未使用额度不累积到下周 |

**额度策略设计理念**：
- **珍惜机制**：有限额度让用户只提交最好的内容，天然过滤低质
- **正向飞轮**：好内容 → 高分 → 更多额度 → 更多好内容被发现
- **防滥用**：上限 + 惩罚机制防止恶意刷分
- **公平性**：所有人初始额度相同，不因粉丝数而不同

#### 👤 模块六：个人中心

**功能描述**：创作者查看自己的评审历史、额度状态、成长轨迹。

**页面内容**：
- 📊 当前额度：剩余次数 / 本周总额度
- 📈 评审历史：所有提交内容的评审报告列表
- 🏆 推荐成功记录：成功进入推荐榜的内容
- 📉 成长曲线：各维度评分随时间的变化趋势
- 🎯 改进建议汇总：AI 给出的所有改进建议聚合

## 四、技术方案

### 4.1 技术栈选型

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| 前端 | React + TypeScript + TailwindCSS | 快速开发，组件化，美观 |
| 后端 | Python (FastAPI) | 异步高性能，AI 生态丰富 |
| 数据库 | SQLite（Demo 阶段） | 轻量，无需额外部署 |
| AI 评审 | OpenAI GPT-4 / Claude API | 评审质量高，支持复杂 prompt |
| AI 检测 | 专用 prompt + 特征分析 | 检测 AI 生成内容 |
| 知乎 API | 搜索 + 圈子 + 直答 | 内容获取 + 结果发布 |
| 部署 | Vercel (前端) + Railway (后端) | 快速部署，免费额度 |

### 4.2 核心 API 调用策略

| 知乎 API | 用途 | 日限额 | 使用策略 |
|-----------|------|--------|----------|
| 知乎搜索 | 获取提交内容的详情 | 1000次/天 | 按需调用，结果缓存 |
| 全网搜索 | 辅助原创性检测（查重） | 1000次/天 | 仅对疑似非原创内容调用 |
| 圈子发布 | 推荐成功内容发布到圈子 | 合理频率 | 仅推荐成功时发布 |
| 圈子点赞 | 对优质内容互动 | 合理频率 | 配合推荐使用 |
| Agent 直答 | 辅助评审 | 100次/天 | 作为补充评审参考 |
| 关注流 | 发现潜在优质内容 | 100次/天 | 缓存，低频调用 |

### 4.4 数据模型设计

```sql
-- 用户表
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    zhihu_id TEXT UNIQUE NOT NULL,
    zhihu_name TEXT,
    avatar_url TEXT,
    weekly_quota INTEGER DEFAULT 3,
    quota_used INTEGER DEFAULT 0,
    quota_week TEXT,  -- 当前额度所属周 (如 "2026-W20")
    total_submissions INTEGER DEFAULT 0,
    total_recommended INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 提交记录表
CREATE TABLE submissions (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,
    content_url TEXT NOT NULL,
    content_title TEXT,
    content_summary TEXT,
    content_author TEXT,
    content_type TEXT,  -- answer/article/pin
    status TEXT DEFAULT 'pending',  -- pending/reviewing/recommended/rejected
    overall_score REAL,
    depth_score REAL,
    originality_score REAL,
    readability_score REAL,
    professionalism_score REAL,
    community_score REAL,
    ai_detection_score REAL,
    review_summary TEXT,  -- 刘看山综合评语
    improvement_tips TEXT,  -- 改进建议 (JSON)
    agent_reports TEXT,  -- 各 Agent 详细报告 (JSON)
    reviewed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 推荐榜记录表
CREATE TABLE recommendations (
    id INTEGER PRIMARY KEY,
    submission_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    content_url TEXT NOT NULL,
    content_title TEXT,
    overall_score REAL,
    recommend_reason TEXT,  -- 刘看山推荐语
    category TEXT,  -- 内容分类
    pin_id TEXT,  -- 知乎圈子发布的想法 ID
    likes_count INTEGER DEFAULT 0,
    views_count INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (submission_id) REFERENCES submissions(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 额度变动记录表
CREATE TABLE quota_logs (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,
    change_amount INTEGER NOT NULL,  -- 正数增加，负数减少
    reason TEXT,  -- submission/reward/penalty/weekly_reset
    submission_id INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

## 五、防作弊与风控机制

### 5.1 内容层面

| 风险 | 防御措施 |
|------|----------|
| AI 生成内容刷分 | 🔍 鉴真山 Agent 专项检测，AI 生成内容扣分 |
| 搬运/洗稿 | 通过知乎搜索 + 全网搜索进行相似度对比 |
| 针对评分标准优化 | 定期调整 Agent prompt，增加随机性 |
| 重复提交 | 同一内容 URL 去重，禁止重复提交 |
| 提交他人内容 | OAuth 身份验证，只能提交自己的内容 |

### 5.2 行为层面

| 风险 | 防御措施 |
|------|----------|
| 批量注册刷额度 | 知乎 OAuth 绑定，一个知乎账号一个系统账号 |
| 恶意消耗额度 | 连续低分惩罚机制 |
| 刷榜行为 | 额度上限 + 同一用户同时在榜数量限制 |

### 5.3 "推荐成功"的双重验证

推荐成功不仅依赖 AI 评分，还结合社区反馈：

```
推荐成功条件 = AI 评审 ≥ 7.0 分（必要条件）

额度奖励条件 = AI 评审 ≥ 7.0 分 + 圈子发布后获得 ≥ 3 个点赞（充分条件）
```

这样确保了推荐内容不仅 AI 认为好，社区用户也认可。

## 十、总结

「刘看山推荐」不是一个简单的内容评分工具，而是一个**重新定义内容发现方式**的产品。它的核心价值在于：

1. **公平**：让内容质量而非粉丝数决定曝光
2. **透明**：每一分都有理由，每个建议都可执行
3. **有趣**：刘看山的人格化让评审过程不再冰冷
4. **正向**：额度机制创造了"越好越多"的正向循环
5. **实用**：不仅评分，更给出可操作的改进建议

> 🦊 刘看山说："在知乎，好内容不该被埋没。让我来帮你找到它们。"
